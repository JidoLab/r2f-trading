# R2F Trading — Security & Reliability Audit Report

## 1. Executive Summary

Your live revenue site has a serious structural problem: **anyone on the internet can grant themselves paid product access and fake payment records**, because PayPal orders are only verified in the browser (client-side), never on your server. The single worst risk is the cluster of unauthenticated, unverified payment/access endpoints — `payment-success` and `starter-kit/purchase` let an attacker mint a working $49-course token and pollute your revenue data with one curl command. Compounding this, several admin and webhook routes have no authentication at all, your admin login token is a guessable non-cryptographic hash, and your GitHub-as-database write path silently loses concurrent writes (lost-update races) across dozens of routes. None of these are theoretical; each has a confirmed exploit path.

## 2. Findings by Severity

### HIGH

**Payment & access bypass (the money cluster)**
- **No server-side PayPal verification on payment-success** — `src/app/api/payment-success/route.ts:5-26` — Anyone can POST fake `orderId`/`amount`/`email` and be recorded as a paying student; also an open email/Telegram spam relay. → Verify the order via PayPal Orders API (needs `PAYPAL_CLIENT_SECRET`) before writing anything; only trust values from PayPal's response.
- **starter-kit/purchase mints a real access token without verifying payment** — `src/app/api/starter-kit/purchase/route.ts:5-43` — POST `{payerEmail, orderId:'anything'}` returns a token unlocking all 18 lessons of the $49 course, free. → Verify the PayPal capture (COMPLETED, $49 USD, not reused) before minting the token.
- **Starter-kit tokens never expire or revoke** — `src/app/api/starter-kit/verify/route.ts:25-35` + `content/route.ts:591-609` — A single leaked/shared token = permanent free course access for anyone. → Add expiry/revocation fields; bind tokens to verified, single-use captures.

**Missing authentication**
- **Admin content-ideas route has zero auth** — `src/app/api/admin/content-ideas/route.ts:21-29, 31-152` — Anonymous POST triggers Claude generation + publishes AI blog posts to your live repo on repeat; unbounded Anthropic cost. → Add `verifyAdmin()` (or `verifyAdminOrCron`) to both GET and POST.
- **Resend webhook signature never actually verified** — `src/app/api/webhooks/resend/route.ts:32-41` — Code only checks a header *exists*; attacker forges open/click events to inflate lead scores to "hot" and corrupt analytics. → Use the `svix` library to verify the HMAC; fail-closed if secret unset.
- **WhatsApp webhook has no signature check** — `src/app/api/whatsapp/webhook/route.ts:88-213` — Forged POSTs drive Claude + WhatsApp send costs and arbitrary GitHub writes. → Verify `X-Hub-Signature-256` HMAC against `WHATSAPP_APP_SECRET` before processing.
- **WhatsApp GitHub path injection** — `src/app/api/whatsapp/webhook/route.ts:107,136` — Unvalidated `senderPhone` interpolated into the repo path lets a forged request overwrite other `.json` data files. → Validate `/^[0-9]{6,15}$/` before use.
- **Telegram webhook has no secret-token check** — `src/app/api/telegram/webhook/route.ts:170-238` — Forged updates trigger uncapped Claude calls + GitHub writes; `from.id` path injection. → Verify `X-Telegram-Bot-Api-Secret-Token`; validate `from.id` is an integer.

**Admin auth weakness**
- **Session token is a 31-bit djb2 hash of the password** — `src/lib/admin-auth.ts:44-54` — The sole admin credential is brute-forceable (~2.1B space, no rate limit), deterministic, and can't be revoked server-side. → Use a high-entropy random or HMAC-signed session token with expiry.

**Data-integrity / race conditions**
- **commitFile retry clobbers concurrent writes (lost update)** — `src/lib/github.ts:28-64` — On a 409 conflict it re-PUTs stale in-memory content, silently destroying the other writer's change. Affects ~27 writers of `subscribers.json` and every read-modify-write route. → Add an `updateJsonFile(path, mutateFn)` helper that re-reads + re-applies the mutation inside the retry loop.
- **Concurrent payments lose records** — `src/app/api/payment-success/route.ts:21-26,124-155` — Two near-simultaneous purchases drop a real payment row. → Route through the atomic update helper; make appends idempotent by `orderId`.

**Cost runaways (the retry-missed cron bug — same root cause, 3 entries)**
- **retry-missed re-fires generate-post daily** — `src/app/api/cron/retry-missed/route.ts:28` — Date check strips hyphens (`20260620`) but filenames use `2026-06-20`, so it always thinks the post "missed" and generates a 2nd full blog post + image/social blast every day. → Match the real filename format (`f.includes(today)`).
- **retry-missed re-fires generate-short daily (3 extra videos)** — `src/app/api/cron/retry-missed/route.ts:77` — Render filenames are title slugs with no date, so the check never matches; 3 extra shorts/day (ElevenLabs + render + commits). → Read each render's `createdAt` instead of the filename.

**Reliability — duplicate sends / public posts**
- **Twitter reply loop exceeds maxDuration** — `src/app/api/cron/twitter-engage/route.ts:257-338` — ~225s of sleep + work blows the 120s ceiling; dedup log saved only at the end, so a timeout re-replies to the same tweets next run (bot-flag risk). → Commit the dedup log incrementally; shrink replyCount/delays.
- **Reddit dedup log loss on commit failure** — `src/app/api/cron/reddit-engage/route.ts:487-492` — Comments post inside the loop but the log saves once at the end with a swallowed catch; a commit failure means duplicate comments next run (you've already had a Reddit ban). → Commit per-comment, or record the postId before posting.
- **Render webhook has no idempotency** — `src/app/api/shorts/webhook/route.ts:69-130` — A retried "succeeded" callback double-uploads the same video to YouTube/FB/LinkedIn. → Early-return if status is already `published`/`ready`.

## 3. Cross-Cutting Patterns

1. **No server-side payment verification.** Both money endpoints trust client-captured PayPal results. This is the root of the worst findings — fix the verification layer and the access-bypass, idempotency, and fake-amount findings all collapse into one fix.
2. **Webhooks without signature verification.** Resend (fake check), WhatsApp, Telegram, and the shorts render webhook all act on unauthenticated bodies — driving Claude/WhatsApp cost, GitHub writes, and data corruption. Every external webhook needs HMAC/secret verification + a rate limit.
3. **Missing auth on "admin" routes.** No `src/middleware.ts` exists, so each route must self-guard. `content-ideas` and `daily-tasks` simply forgot `verifyAdmin()`. A global middleware matcher for `/api/admin/*` would prevent recurrence.
4. **GitHub-as-database has no concurrency control.** `commitFile`'s retry re-applies stale content instead of re-merging — a single root cause behind nearly every data-integrity finding (subscribers, payments, queues, suggestions, tip counter). One `updateJsonFile(path, mutateFn)` helper fixes the whole class.
5. **Persist-after-work pattern causes duplicate sends.** reddit-engage, twitter-engage, whatsapp-drips all do the irreversible action (post/send) first and persist the dedup record last, so any timeout/commit-failure replays the action. Persist incrementally or before the action.
6. **Date-format mismatches in cron health checks.** The hyphen-stripping `replace(/-/g,"")` bug appears 2-3x in `retry-missed` — same class already fixed for reddit-engage but missed elsewhere.
7. **Weak admin credential.** The djb2 token + `|| "admin"` fallback undermine every auth check that does exist.

## 4. Recommended Fix Order

1. **Server-side PayPal verification** (`payment-success` + `starter-kit/purchase`) — add `PAYPAL_CLIENT_SECRET`, verify order COMPLETED + amount/currency before any write or token mint. Closes the revenue-bypass, fake-record, and amount-injection findings at once.
2. **Add auth to the two unguarded admin routes** (`content-ideas`, `daily-tasks`) — one-line `verifyAdmin()` each; stops live token-burn and repo pollution today.
3. **Replace the admin session token** with a random/HMAC-signed value + remove the `|| "admin"` fallback.
4. **Verify all webhook signatures** (Resend via svix, WhatsApp HMAC, Telegram secret-token, shorts render) + add per-sender rate limits and `senderPhone`/`from.id` validation.
5. **Fix the retry-missed date checks** (generate-post + generate-short) — stops daily duplicate blog posts and 3 extra videos/day. Cheap, high cost-savings.
6. **Build `updateJsonFile(path, mutateFn)`** and migrate `subscribers.json`/`payments.json`/queue writers — fixes the lost-update class.
7. **Make engagement/send crons persist incrementally** (reddit, twitter, whatsapp-drips) + render-webhook idempotency — stops duplicate public posts/comments (account-suspension risk).
8. **Suppression list for unsubscribe + hard bounces** — CAN-SPAM and Resend reputation.
9. **Rate-limit + bound the public LLM/email endpoints** (chat, crash-course, track).
10. Work through remaining MEDIUM, then LOW as cleanup.
